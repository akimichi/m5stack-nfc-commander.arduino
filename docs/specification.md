# m5stack-nfc-commander 仕様書

- 版: 0.1（ドラフト）
- 作成日: 2026-08-18
- 対象: M5Stack CoreS3 + NFC Universal Unit (U216 / ST25R3916)

---

## 1. 目的

NFCカードをかざすと、そのカードから読み取った情報を、USB接続されたPCに
**USB HIDキーボードのキー入力として送出する**デバイスを実装する。

PC側には専用アプリケーションを一切必要とせず、テキストエディタ・表計算ソフト・
Webフォームなど、キーボード入力を受け付けるあらゆる場所にそのまま入力できる。
位置づけとしてはバーコードリーダーのNFC版である。

## 2. スコープ

### 2.1 対象

| 項目 | 内容 |
|---|---|
| 対応カード | NFC-A (ISO/IEC 14443 Type A) のみ |
| 読取データ | カードUID、および NDEF Text レコード |
| NDEF 対応タグ | NFC Forum Type 2/4 (NTAG, Ultralight 等) と **MIFARE Classic** |
| PC出力 | USB HID キーボード（CoreS3 が USB Device 側） |
| 開発環境 | PlatformIO CLI / Arduino framework (espressif32) |

### 2.2 対象外（本版では実装しない）

- NFC-B (ISO14443B) / NFC-F (FeliCa) / NFC-V (ISO15693) の読み取り
- カードへの書き込み、カードエミュレーション
- ネットワーク機能（Wi-Fi / BLE）

> リポジトリ名 `nfc-commander` が示唆する「カード → 任意文字列送出」機能は F-12 で扱う。
> 修飾キーや特殊キーを含むキーシーケンスの送出は対象外とし、単純な文字列のみを扱う。

## 3. アーキテクチャ上の前提（重要）

CoreS3 の USB-C ポートは ESP32-S3 のネイティブUSB(OTG)に直結した**1ポートのみ**であり、
USB Host モードと USB Device モードは**排他**である。

本プロジェクトで PC にデータを送る動作は、CoreS3 が **USB Device（ペリフェラル）**
として振る舞うものであり、USB Host 機能は使用しない。
（USB Host は CoreS3 に USB機器をぶら下げる場合に使う、逆方向の機能である。）

この結果として次の制約が生じる。

- プログラム書き込み用ポートと HID 出力ポートが同一である。
- 実行中は PC から「キーボード」として見えるため、書き込み時はダウンロードモードへ
  手動で入る操作が必要になる場合がある（§9 参照）。

## 5. ソフトウェア構成

### 5.1 依存ライブラリ

| ライブラリ | 用途 | 備考 |
|---|---|---|
| `m5stack/M5Unified` | 本体・LCD・スピーカー・I2C初期化 | |
| `m5stack/M5Unit-NFC` | ST25R3916 制御 | v0.1.0 と新しいためバージョン固定する |
| `m5stack/M5UnitUnified` | 上記の依存 (>=0.5.0) | |
| Arduino ESP32 `USBHIDKeyboard` | HIDキーボード出力 | TinyUSB |

M5Unit-NFC の主要API（サンプル `examples/UnitUnified/NFCA/Detect` より）:

```cpp
m5::unit::UnitNFC unit{};           // I2C ユニット
m5::nfc::NFCLayerA nfc_a{unit};     // NFC-A レイヤ
nfc_a.detect(std::vector<PICC>&);   // カード検出
nfc_a.identify(picc);               // 種別確定
picc.uidAsString();                 // UID文字列
picc.typeAsString();                // カード種別文字列
nfc_a.deactivate();                 // 非活性化
```

### 5.2 ビルド構成

USB を TinyUSB モードに切り替えるため、以下のフラグを設定する。

```ini
[env:release]                 ; 製品ビルド: HIDのみ
build_flags =
  -DARDUINO_USB_MODE=0        ; TinyUSB を使用（HID に必須）
  -DARDUINO_USB_CDC_ON_BOOT=0 ; CDC無効（M5CoreS3系ライブラリとの既知衝突を回避）

[env:debug]                   ; 開発ビルド: HID + CDC 複合
build_flags =
  -DARDUINO_USB_MODE=0
  -DARDUINO_USB_CDC_ON_BOOT=1
  -DNFCCMD_DEBUG_LOG=1
```

> `ARDUINO_USB_CDC_ON_BOOT=1` と M5CoreS3 ライブラリ (`I2C_IMU.cpp` の `USBSerial` 参照)
> の衝突が報告されている。本プロジェクトは M5CoreS3 ではなく M5Unified を使用して回避する。

#### USB 初期化順序の制約（実装上の必須事項）

Arduino ESP32 core は `ARDUINO_USB_ON_BOOT`（= `CDC_ON_BOOT | MSC_ON_BOOT | DFU_ON_BOOT`）
が真のとき、`setup()` より前の `app_main()` で `USB.begin()` を呼ぶ。
一方 `USBHIDKeyboard` は**コンストラクタ**で HID インターフェースを USB ディスクリプタへ
登録する（`hid.addDevice()`）。

このため `USBHIDKeyboard` のインスタンスは**グローバル変数として宣言し、静的初期化の
段階で登録を済ませておかなければならない**。`setup()` 内や関数内 `static` で生成すると、
debug ビルド（`CDC_ON_BOOT=1`）では登録が `USB.begin()` に間に合わず、
PC からキーボードとして認識されない。

`USB.begin()` 自体は、`CDC_ON_BOOT=0`（release ビルド）のときのみアプリ側で呼ぶ。

## 6. 機能仕様

### F-01 カード検出

- ポーリング周期: 既定 100 ms（設定可能: 50〜500 ms）
- `NFCLayerA::detect()` により NFC-A の PICC を検出する。
- 複数枚が同時に検出された場合は**どのカードも処理しない**。LCDに警告を表示し、
  警告音を鳴らす。どのカードを読むべきか決定できない状態で出力すると、
  PC に誤った入力を送ってしまうためである。
- 検出後は `identify()` でカード種別（MIFARE Classic / Ultralight / NTAG など）を確定する。

### F-02 UID取得

- UID（4/7/10バイト）を取得し、**大文字16進・区切りなし**の文字列に変換する。
  - 例: `04A2B3C4D5E680`
- 大文字/小文字、区切り文字（なし / `:` / `-`）は設定可能とする。
  ただし §8-3 のレイアウト制約により、既定は「大文字・区切りなし」とする。

### F-03 NDEFテキスト読み出し

- カードが NDEF 対応（NTAG / MIFARE Ultralight 等）の場合、NDEF メッセージを読み出し、
  **最初の Text レコード (TNF=Well Known, Type='T')** の本文を取得する。
- 取得できない場合（非対応カード、NDEF未書き込み、読み出し失敗）はエラーとせず、
  「NDEFなし」として扱い後続処理を継続する。
#### MIFARE Classic への対応

MIFARE Classic は規格上 NFC Forum Tag Type 1〜5 のいずれでもないため、
ライブラリの `NDEFLayer` では読み出せない。しかし実運用で広く使われているため、
本プロジェクトでは専用の読み出し経路を設ける。

1. セクタ 0 のブロック 1〜2 にある **MAD (MIFARE Application Directory)** を
   MAD 鍵 `A0A1A2A3A4A5` (Key A) で認証して読む。
2. MAD のエントリが AID `0x03E1` を示すセクタが NDEF データセクタである。
3. 各 NDEF セクタを **NFC Forum 公開鍵 `D3F7D3F7D3F7`** (Key A) で認証し、
   ブロック 0〜2 (48バイト) を読み出して連結する。
4. 連結したデータを TLV として解析し、NDEF Message TLV (`0x03`) を取り出す。

鍵が既定値から変更されているカードは読み出せない。これは仕様上の制限とする。
鍵の探索や総当たりは行わない。

- Text レコードのペイロードは `[status][言語コード][本文]` の構造を持つ。
  status の下位 6 bit が言語コード長を表すため、これを読み飛ばして本文だけを取得する。
- status の bit7 が立っている場合、本文の符号化は UTF-16 である。
  UTF-16 は HID キーボードで打鍵できないため、**「NDEFなし」として扱う**。
  サニタイズに任せると本文が虫食い状態で出力されてしまうためである。
- 読み出し上限: 256 バイト（超過分は切り捨て、LCDに切り捨て表示）。

### F-04 出力モード

以下の3モードを設定で切り替える。既定は `UID_ONLY`。

| モード | 出力内容 | NDEF未取得時の挙動 |
|---|---|---|
| `UID_ONLY` | UIDのみ | — |
| `NDEF_ONLY` | NDEFテキストのみ | UIDにフォールバック |
| `UID_AND_NDEF` | `UID` + 区切り + `NDEFテキスト` | UIDのみ出力 |

- 中間区切り: Tab（既定） / Space / カンマ から選択可能。
- 終端キー: Enter（既定） / Tab / なし から選択可能。

> **区切り文字は文字列に埋め込まない。** Tab (0x09) は F-05 のサニタイズ範囲
> (0x20〜0x7E) の外にあり、文字列に混ぜると除去されてしまうためである。
> formatter は出力を**フィールドの並び**として返し、hid_output がフィールド間に
> 区切りをキーとして送出する。これにより、
> 「formatter が生成した制御された区切り」と
> 「NDEF テキストに紛れ込んだ予期しない制御文字」を明確に区別できる。

### F-05 HIDキーボード出力

- `USBHIDKeyboard` により、F-04 で組み立てた文字列を打鍵する。
- 打鍵間隔: 既定 8 ms/文字（設定可能: 0〜50 ms）。
  受信側アプリの取りこぼしを防ぐため、既定値は 0 にしない。
- サニタイズの結果が空文字列になった場合は、**終端キーも送らない**。
  Enter だけが単独で送られ、PC 側で意図しない確定操作になるのを避けるためである。
- **サニタイズ**: 出力対象は ASCII 印字可能文字 (0x20〜0x7E) のみとする。
  範囲外のバイト（日本語・制御文字・絵文字など）は既定で**破棄**し、
  LCDに除外したバイト数を表示する。設定により `?` への置換も選択できる。
  置換の場合、連続する範囲外バイト列はまとめて 1 個の `?` にする。
  UTF-8 の 1 文字が `???` に化けるのを避けるためである。
- **キーボードレイアウト**: `US`（既定）/ `JIS` を設定で選択する。
  JIS選択時は US とキー位置が異なる記号を変換テーブルで補正する。

  ただし `0-9` `A-Z` `Enter` `Tab` `Space` は両レイアウトでキー位置が同一であり、
  **UID を出力する限りレイアウトの影響を受けない**。レイアウト差が問題になるのは
  NDEF テキストに記号が含まれる場合だけであるため、この実装は NDEF を扱う
  S-7 で行う（§11）。それまでは US 配列固定として扱う。

  なお JIS 配列固有のキー（`\` = INTERNATIONAL1/3 など）は、`USBHIDKeyboard::write()`
  が持つ US 配列前提の ASCII 変換表では送出できない。ただし `pressRaw()` /
  `releaseRaw()` が生の HID キーコード（0x00〜0xA4）を受け付けるため、
  HID レポートを自前で組み立てる必要はない。S-7 ではこれを用いる。

### F-06 多重読み取り防止

本機能の目的は、カードを置いたままにしたときにPCへ同じ入力が連打されるのを防ぐことである。

1. 同一UIDのカードが電界内に留まっている間は、**最初の1回のみ**出力する。
   置きっぱなしでも繰り返し出力しない。
2. カードの離脱は、`detect()` が**連続 `absent_threshold` 回**（既定 3 回、
   ポーリング周期 100ms なので約 300ms）カードを検出しなかったことで判定する。
3. 離脱を検知した時点で抑止を解除する。同じカードを再びかざせば出力される。
4. ただし同一UIDの連続出力は、前回出力から `debounce_ms`（既定 500ms）以内は行わない。
   カード位置のふらつきによる離脱・再検出の往復（チャタリング）を吸収するためである。
5. **異なるUIDのカードは、上記 4 に関わらず即座に出力する。**
   別のカードに持ち替えた操作を待たせる理由がないためである。
6. 処理完了ごとに `deactivate()` を呼び、次の検出に備える。

> `NFCLayerA::isActive()` はカードの在圏判定には使えない。RF通信を行わず、
> 内部に保持した `_activePICC` との一致を返すだけであり、`deactivate()` 後は
> 常に false になるためである。離脱判定は上記 2 の方法で行う。

### F-07 出力の有効/無効トグル（誤爆防止）

HIDキーボードは任意の文字列をPCに打ち込めるため、意図しない打鍵を防ぐ手段を設ける。

- LCDタッチ、または本体ボタンで **出力ON / OFF** をトグルする。
- OFF時はカードを検出してもHID出力を行わず、LCD表示とビープのみ行う。
- 現在の状態はLCD上部に常時表示する（ON=緑 / OFF=赤）。
- 起動直後の既定状態は **OFF** とし、ユーザーの明示操作で有効化する。

### F-10 設定の永続化

NVS (Preferences) に以下を保存する。namespace: `nfccmd`

| キー | 型 | 既定値 | 許容範囲 |
|---|---|---|---|
| `out_mode` | uint8 | `UID_ONLY` | 0〜2 |
| `uid_case` | uint8 | 大文字 | 0〜1 |
| `uid_sep` | uint8 | なし | 0〜2 |
| `mid_sep` | uint8 | Tab | 0〜2 |
| `term_key` | uint8 | Enter | 0〜2 |
| `key_delay` | uint16 | 8 (ms) | 0〜50 |
| `layout` | uint8 | US | 0〜1 |
| `debounce` | uint16 | 500 (ms) | 0〜5000 |
| `absent_threshold` | uint8 | 3 (回) | 1〜20 |
| `poll_ms` | uint16 | 100 (ms) | 50〜500 |
| `nonascii` | uint8 | 破棄 | 0〜1 |

読み出した値が許容範囲の外にあった場合は、その項目だけを**既定値に戻す**。
NVS の内容が壊れていたり、旧版で保存された値が残っていても起動できなくなることを
避けるためである。設定全体を破棄することはしない。

#### 設定画面の操作 (S-8b で確定)

読み取り画面で**画面を長押し**すると設定画面へ入る。設定画面を表示している間は
NFC の読み取りを止める。設定中に意図しない打鍵が起きるのを防ぐためである。

```
┌─────────────────────────────────┐
│ SETTINGS                  2/11  │  項目位置
├─────────────────────────────────┤
│   Output mode       UID+NDEF    │
│ > UID case          UPPER       │  選択中の行は反転表示
│   UID separator     NONE        │
│   Field separator   TAB         │  選択位置に応じてスクロールする
│   Terminator        ENTER       │
│   Key delay         8 ms        │
├─────────────────────────────────┤
│  [ NEXT ]  [ CHANGE ]  [ BACK ] │  画面下部を 3 分割したタッチ領域
└─────────────────────────────────┘
```

| ボタン | 動作 |
|---|---|
| NEXT | 次の項目へ移る。末尾なら先頭へ戻る |
| CHANGE | 選択中の項目の値を次の候補へ進める。末尾なら先頭へ戻る |
| BACK | 設定を NVS に保存して読み取り画面へ戻る |

値はすべて候補からの循環選択とし、数値項目も候補を並べる。任意の数値を入力する
手段は設けない。3 つのボタンだけで全項目を編集できるようにするためである。
候補はいずれも本節の許容範囲に収まる値とする。

| 項目 | 候補 |
|---|---|
| Key delay | 0 / 4 / 8 / 16 / 32 / 50 ms |
| Debounce | 0 / 250 / 500 / 1000 / 2000 / 5000 ms |
| Absent count | 1 / 2 / 3 / 5 / 10 / 20 回 |
| Poll interval | 50 / 100 / 200 / 300 / 500 ms |

### F-11 エラー処理と復旧

| 事象 | 挙動 |
|---|---|
| ユニット未接続（`Units.begin()` 失敗） | LCDに接続案内を表示し、2秒間隔で再初期化を試行し続ける |
| ユニットが応答しなくなった | 1秒間隔の生存確認が3回連続で失敗したらバスを解放して再初期化する |
| I2C バスの固着 | 再初期化を3回試すごとに1回、バス解放も行う。9回試しても戻らなければLCDに電源再投入を促す |
| Port A の SCL LOW 固着（既知問題） | 起動時の初期化順序は `M5.begin()` に委ね、上記のバス解放で回復を試みる |
| USB未接続でHID出力要求 | 出力をスキップし、LCDに「PC未接続」と表示する |

#### 生存確認の方法

カードの有無とは無関係にユニット自体の生存を判定する必要があるため、
**I2C アドレスへの送信に ACK が返るか**で確かめる。`detect()` の失敗回数では
「カードが置かれていないだけ」と区別できない。

#### 再初期化の制約

`UnitUnified::add()` は登録済みのユニットに対して false を返すため、
**登録は初回のみ**行い、再初期化では `UnitUnified::begin()` だけを呼ぶ。
再初期化のたびに `add()` からやり直すと必ず失敗する。

#### バス解放の手順

スレーブがバスを掴んだまま（SDA を LOW に保持）になると以後の通信がすべて
失敗する。SCL を 9 回トグルして残りのビットを吐き出させ、STOP 条件を送って
解放させたうえで、I2C を開き直す。

### F-12 カードごとの文字列送出

カード UID と送出する文字列の対応表を SD カードに置き、かざしたカードに応じた
文字列を PC へ送る。社員証で定型文を入力する、といった用途を想定する。

#### 対応表の形式

SD カード直下の **`/nfc_commands.csv`** を起動時に読み込む。

```csv
# 行頭が # の行と空行は読み飛ばす
04A2B3C4D5E6,Hello World
A3:7A:1B:DD,user@example.com
0411223344,  前後の空白は取り除く
```

- 1 列目は UID の 16 進表記。大文字小文字を問わず、`:` と `-` は無視する。
- 2 列目以降が送出する文字列。**最初のカンマより後ろすべて**を値とするため、
  文字列中にカンマを含められる。
- 前後の空白は取り除く。
- UID が不正な行、値が空の行は読み飛ばす。ファイル全体を無効にはしない。
- 同じ UID が複数回現れた場合は**後の行を優先する**。
- 登録できる件数の上限は 500 件とする。

#### 出力モードとの関係

出力モード (F-04) に `COMMAND` を追加する。

| モード | 出力内容 |
|---|---|
| `COMMAND` | 対応表にある文字列。**未登録のカードは UID を出力する** |

既定は従来どおり `UID_ONLY` であり、`COMMAND` を選んだときだけ対応表を参照する。
SD カードが無い、ファイルが無い、読み込みに失敗した場合は対応表が空になり、
すべてのカードが UID にフォールバックする。エラーとはしない。

送出時のサニタイズ (F-05) と終端キー (F-04) は他のモードと同じ扱いとする。
したがって非 ASCII 文字は打鍵できない。

#### 注意

対応表は**平文で保存される**。SD カードを抜けば内容を読み取れるため、
パスワードなど秘匿性の高い文字列を登録する用途には適さない。

## 8. 制約・既知のリスク

1. **書き込みポートとHIDポートが同一**。`ARDUINO_USB_MODE=0` に切り替えると
   USB-Serial/JTAG が無効になり、自動書き込みに失敗する場合がある（§9 の手順で対処）。
2. **`ARDUINO_USB_CDC_ON_BOOT=1` と M5CoreS3 ライブラリの衝突**が既知。
   M5Unified を使用して回避する。
3. **HIDはPC側のキーボードレイアウトに依存する**。
   `0-9` `A-Z` `Enter` `Tab` は US/JIS 共通のため UID出力は安全だが、
   NDEFテキストに記号が含まれる場合はレイアウト設定 (F-05) が必須。
   日本語は HID キーボードでは原理的に打鍵できないため出力できない。
4. **CoreS3 Port A の I2C ハング問題**（USB完全電源断後に AW9523B の `BUS_OUT_EN`
   未初期化で SCL が LOW に固着する事例が報告されている）。F-11 で対処する。
5. **M5Unit-NFC は v0.1.0** と若く、API変更の可能性がある。
   `platformio.ini` でバージョンを固定し、`nfc_reader` モジュールで隔離する。
6. **消費電流**。LCDバックライト + NFC RF送信で数百mA を要する。
   USBバスパワーで不足する場合はバックライト輝度を落とす。
7. **セキュリティ**: 本デバイスは PC に対して任意のキー入力を送出できる。
   F-07 の出力トグルと、起動時OFF既定によって誤爆・悪用リスクを緩和する。
8. **CoreS3 は LCD と SD が SPI バスを共有する**。M5GFX がバスを保持したまま
   `SPI.end()` を呼ぶと解放処理から戻らず停止する。SD の利用後は `SD.end()` で
   マウントを解除するにとどめ、SPI バスは開いたままにする (F-12)。
   実機で `setup()` が停止し、UNIT NG が消えずタッチも効かない不具合として
   発現した。2026-08-27 に修正済み。

## 9. 開発・ビルド・書き込み手順

```bash
# ビルド
pio run -e debug

# 書き込み
pio run -e debug -t upload

# ホスト側テスト
pio test -e native
```

**シリアルモニタは使えない。** `debug` ビルド (`ARDUINO_USB_MODE=0`) では USB を
TinyUSB が占有する一方、`M5_LOGI` などのログは `::printf` 経由で ESP-IDF の
コンソール (UART0 = G43/G44) に出るため、USB CDC には流れてこない。
`pio device monitor` を開いても何も表示されない。実機の状態確認は LCD 表示で行う。

### 手動ダウンロードモードでの書き込み

`ARDUINO_USB_MODE=0` の実機では esptool の自動リセットが効かず、
`pio run -t upload` は `Failed to connect to ESP32-S3` で失敗する。
書き込みのたびに以下の手順が必要である。

1. USB を接続したまま、CoreS3 の電源ボタン（左側面）を押し続ける
2. **本体の緑 LED が点灯した瞬間に離す**（およそ3秒。長すぎると電源OFFになる）
3. `Espressif USB JTAG/serial debug unit` として再列挙されたことを確認する
   （`lsusb` で `303a:1001` / `bcdDevice 1.01`）
4. `pio run -e debug -t upload` を実行する
5. 書き込み後は自動で復帰しないため、**電源ボタンを短く押して起動する**
